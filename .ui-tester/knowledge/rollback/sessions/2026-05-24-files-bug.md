## Root Cause Analysis

### Bug Location
File: `pi-agent-chat/src/shared/agent/process-manager.ts`, line 1996-2026

### Root Cause
The `getModifiedFiles` method only works with an ACTIVE managed session (a running pi subprocess).
When a session is loaded from JSONL (no active process), it immediately returns `[]`:

```typescript
async getModifiedFiles(sessionId, fromEntryId, toEntryId, toUserMsgEntryId) {
    const managed = this.getActiveManaged(sessionId);  // Returns null for JSONL sessions
    if (managed) {
      // ... calls managed.client.getModifiedFiles() ...
      return result;
    }
    console.log("[PM] getModifiedFiles no managed session, returning []");
    return [];  // <-- BUG: Returns empty array for JSONL sessions
}
```

### Key Evidence
1. `getActiveManaged` checks `this.clients.get(sessionId)` which only has entries for running processes
2. JSONL-loaded sessions (after page refresh, or viewing historical sessions) don't have a managed client
3. The `snapshot.list` handler in `snapshot.ts` ALREADY has a JSONL fallback (readStepSnapshots)
4. But `getModifiedFiles` was never given a similar fallback

### Fix Direction
Add a JSONL fallback to `getModifiedFiles` that:
1. Reads step-snapshot entries from the JSONL file (using existing `readStepSnapshots` function)
2. Filters snapshots by `toUserMsgEntryId` to find the target turn
3. Computes the file diff from the step-snapshot data
4. Returns the file list in the expected format
